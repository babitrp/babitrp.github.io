01 The problem

From one script per design to a single, validated platform.

Choosing a dose-escalation design meant a separate script for each design and scenario. Comparing operating characteristics took days, and live dose decisions depended on whoever owned the code.

02 Why existing approaches fell short

What the old workflow couldn't do.

Each published design comes as its own script or package with its own inputs and outputs, so a like-for-like comparison needs custom glue code. Nothing gave statisticians one interface for both pre-study simulation and live dose decisions.

05 Difficult engineering decisions

Decisions, trade-offs and how quality was assured.

Decisions & trade-offs
  • Simulations as background jobs. Statisticians keep working while thousands of trials compute. Trade-off: job state and progress have to be managed explicitly.
  • MCMC (JAGS) for model-based designs. Flexible priors for BLRM and combination designs. Trade-off: slower runs, which is why seeds and async execution matter.
  • Setup changes reset dependent results. No result can silently refer to an old setup. Trade-off: users re-run designs after changing doses, by design.
Challenges
  • Thousands of MCMC trials per scenario. Simulations run asynchronously in the background, so the interface stays responsive and several designs can be compared in one session.
  • Reproducibility. Seeds on every stochastic step, and parameter sets that can be saved and reloaded.
  • Stale results. Changing the study setup clears every design, analysis and scenario that depends on it.
  • Seven designs, one interface. Each design family shares the same setup, analysis and simulation flow.
Validation

An internal tool, validated for use by the biostatistics team that uses it.

Operating characteristics

3+3: standard cohorts of three with the 1/6 expansion rule. BOIN: Liu & Yuan (2015) boundaries with φ₁ = 0.6φ, φ₂ = 1.4φ, dose elimination at P(p > φ) > 0.95 and MTD chosen by isotonic regression. The right dose is the one whose true DLT rate is closest to the target.

What it does

One place to choose a design, defend it and run it.

01 Set up

Study setup

Number of dose levels, dose values and units. Changing the setup resets any design, analysis and scenario that depends on it, so stale results can't carry over.

02 Design

Seven designs, side by side

Single agent: 3+3, mTPI, mTPI-2 (Keyboard), BOIN and the Bayesian logistic regression model (BLRM). Toxicity and efficacy together: joint modelling (JMTE). Two agents: a logistic combination model. Any number of variants can be added, each with its own parameters, decision table and prior plots.

03 Simulate

Operating characteristics

Enter true toxicity scenarios and run thousands of trials per design: how often each dose is chosen, patients and DLTs per dose, and the spread of sample sizes. Results export to a PDF report.

04 Analyse

Live dose recommendation

Enter each cohort's dose, patients and DLTs as the trial runs. The platform returns the next dose with the evidence behind it: the decision table, the updated dose-toxicity curve, and the probability that each dose is under, on or over target.

05 Optimise

Pick the winner

For the randomised stage after escalation, a go/no-go and dose-selection rule between a low and a high dose, with the decision threshold tuned for a chosen trade-off.

06 Trace

Reproducible by default

Seeds on every stochastic step, saved and reloadable parameter sets, and a session panel with R and package versions, changelog and test evidence.
